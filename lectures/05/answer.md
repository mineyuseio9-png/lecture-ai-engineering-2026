## 宿題

- 取り組んだレベル：基礎
- やったこと（変更したファイル・設定・処理、または設計した取得方法）：`app/config.py` の `RAG_TOP_K` を5から3に変更し、ベクトル検索で取得するページ数が回答の処理時間やトークン数、API費用に与える影響を検証した。
- 比較した質問と、固定した条件（モデル・対象資料など）：「第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？」という同一の質問を使用した。回答モデルと対象資料を固定し、検索件数のみ変更した。
- 結果（変更前後の回答・根拠、`--trace`の出力、時間・トークン数・生成API推定費用など）：

| 項目 | 変更前（5件） | 変更後（3件） |
|---|---|---|
| 回答時間 | 2.96秒 | 3.00秒 |
| 入力トークン数 | 3,037 | 2,079 |
| 出力トークン数 | 208 | 181 |
| モデル応答回数 | 2回 | 2回 |
| 生成API推定費用 | $0.001431 | $0.001076 |
| 検索で取得した根拠 | 第2回 p.52を含む | 第2回 p.52を含む |

- 改善した例と、残る失敗・制約：検索件数を5件から3件に減らした結果、入力トークン数が約31.5%、生成API推定費用が約24.8%削減された。一方、回答時間は2.96秒から3.00秒となり、明確な短縮は見られなかった。どちらも第2回p.52を取得できたが、最終回答の正確性については追加検証が必要である。
- 気づき・疑問：検索件数を減らすことで、必要な根拠を維持しながらトークン数と費用を削減できる可能性があると分かった。検索件数を増やすことよりも、質問に必要な情報を適切に選ぶことが重要だと感じた。
